# Retrospective cached Llama sandbox evaluation

20 November 2026 IST. This protocol covers a secondary evaluation of the cached Llama 3.2 3B Instruct Q4_K_M checkpoint. The 360-case subset, three grouped splits and label rules already exist in the frozen sandbox benchmark. Earlier native Qwen results exist on the larger parent pool. This evaluation uses its own model and feature manifest. It supplies no new untouched test set or certified ScienceWorld labels.

1. Read last and mean candidate-action token vectors on single unpadded prompts. Use the frozen research prompt content in the cached Llama no-tools template, with its exact system prefix and BOS. Keep 28 block inputs and the per-token final output. Validate UTF-8 byte reconstruction, span coverage, matched action IDs and a causal suffix check on excluded inputs. Pin checkpoint blob, template, source and binary hashes before the run.
2. Measure latency and resource use on excluded examples across all four domains. Use the 360-case pre-frozen subset only if twice the slowest measured forward projects below 20 minutes and the output estimate fits above the existing 6 GiB disk reserve. Record the decision before model evaluation. Make no scale or hyperparameter choice from model accuracy. Keep one model resident and retain the live memory and swap guard.
3. Fit linear L2 probes with the existing training standardizer and development-only C and layer rules, using the three frozen splits. Evaluate horizon 3 with binary and three-class labels, last and mean pooling, and all-data and intact-pair subsets. Include action-only lexical and majority baselines, embedding layer, ten shuffled-label runs, and the fixed-verb control. Run horizon 1/2 checks with the primary last/all design. Keep the original transfer gate open because the subset contains only sandbox cases.
4. Use the raw stated-output records for the same checkpoint and benchmark IDs if that generation route fits the measured budget. Record missing outputs and evaluate pair correctness only on eligible complete pairs. Report grouped intervals, exact denominators and seed overlap. Avoid pooling these results with BF16 or native Qwen results. Preserve scripts, fitted-model selection receipts, predictions, logs and the offline handoff.
